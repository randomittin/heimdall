# Durable-backend (Firestore) + durable-execution (Cloud Run Jobs) runtime deps — Wave 2.
#
# bin/lib/cp_state_firestore.FirestoreBackend talks to Google Cloud Firestore when
# HEIMDALL_STATE_BACKEND=firestore. The shipped backend imports google.cloud.firestore
# LAZILY (only when the firestore backend is actually selected), so the default 'local'
# backend never needs this dep — installing it is required ONLY for the durable Cloud
# Run deployment, not for dev/test/laptop use.
#
# bin/lib/cp_jobrunner.CloudRunJobRunner.dispatch runs the long job OUT OF PROCESS via the
# Cloud Run Jobs REST API (google.cloud.run_v2.JobsClient.run_job) over the runtime SA's
# ADC — the deployed image has NO gcloud SDK, so without google-cloud-run the prod dispatch
# returns {dispatched: False} and the job stays queued forever. cp_jobrunner imports run_v2
# LAZILY (only the cloudrun-job runner needs it), so the thread/subprocess (local/dev/test)
# paths never require this dep either.
#
# The firestore client also routes to the Firestore emulator automatically when
# FIRESTORE_EMULATOR_HOST is set (used by test/cp-durability.test.sh when an emulator is
# available), so that pin serves both the real deploy and the emulator path.
#
# Pinned for reproducible image builds, matching the Dockerfile's pin discipline
# (cryptography==42.0.8). The Dockerfile pins MUST match these EXACTLY (firestore 2.16.1,
# run 0.10.19). Deploy owner: pip-install these in the image alongside the cryptography pin.
google-cloud-firestore==2.16.1
google-cloud-run==0.10.19
