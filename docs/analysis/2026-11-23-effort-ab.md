# Subagent thinking effort A/B: medium vs high (2026-11-23)

Status: **DESIGN FROZEN** (committed before any measured run; sections 1-4 never change after data). Results, verdict and spend are section 5 onward.
Context: lever 3 of `docs/analysis/2026-11-22-token-utilization-next.md` (local-only doc): subagent output is 19.0M tokens, about 88% hidden thinking; the "15-25% output cut at medium" was an estimate (INF), never measured. `agents/heimdall.md` (Effort ladder) and `skills/heimdall/references/agent-templates.md` now tell the orchestrator to spawn bounded jobs at `low`/`medium` and rerun one step up on a subpar result. This A/B decides whether `medium` is the right default for those jobs.

## 1. The effort switch (verified before the design was frozen)

- Switch: `claude --effort <low|medium|high|xhigh|max>` (Claude Code 2.1.330 `--help`). `CLAUDE_CODE_EFFORT_LEVEL` is not used: the child environment is scrubbed (section 3.4), so only the flag acts.
- Probes, `--safe-mode`, no tools, model alias `sonnet` (resolved to `claude-sonnet-5-5` in the init event), `result.usage.output_tokens` (includes hidden thinking; thinking text is not exposed, `thinking_display: updates`) and the CLI's `thinking_tokens` estimate:

| prompt | low | medium | high | max |
|---|---|---|---|---|
| 3x12 domino tilings (1 sample each) | 109 out / est 198 | 109 / 198 | 113 / 200 | not run |
| 8-digit permutations divisible by 11, sample a | 517 / 383 | 552 / 390 | 552 / 398 | 1030 / 950 |
| same, sample b | 578 / 450 | 524 / 376 | 622 / 500 | 1428 / 1350 |

- Reading: the switch is live (max is 1.8-2.8x high on the same prompt, same correct answer 4608), but low, medium and high are inside sample noise on these two small prompts. So a medium-vs-high token gap on small tasks may be small, and NO-GO on the token criterion is a live outcome. The A/B, not the probe, decides.

## 2. Existing infrastructure considered

- `evals/benchmark/run.sh` / `bin/benchmark` / `bin/heimdall-bench`: raw Claude Code vs hmd (the arms differ by DRIVER), 5 heavy tasks (multi-file feature, fullstack scaffold), no effort dimension, JSONL appended to a gitignored `results.jsonl`. Wrong comparison and too heavy for 40 runs. Reused: the conventions (fresh git workspace seeded from files, a runnable oracle, usage and cost read from the CLI's own accounting).
- `bin/heimdall-self-improve`: a routing-experiment loop over `metrics.jsonl`, not a headless-run harness. Not a fit.
- So: a small dedicated harness, `evals/effort-ab/` (runner `run.py`/`run.sh`, analysis `analyze.py`, fixtures `tasks/`, proof `test/effort-ab.test.sh`).

## 3. Design (frozen)

### 3.1 Tasks: 10 fixed, self-contained, objectively graded

Each `tasks/<id>/` has `task.json` (id, title, difficulty, lang, the exact prompt), `seed/` (real code plus a PARTIAL visible test the agent can run), `accept.sh` (HIDDEN acceptance, exit 0 = pass; stricter than the visible tests, but every behaviour it asserts is stated in the prompt or the seed docstrings), `reference/` (a correct solution overlay). Hidden tests live in the task dir, never in the agent's workdir. `test/effort-ab.test.sh` proves each fixture is falsifiable: seed FAILS acceptance, seed+reference PASSES.

| id | difficulty | lang | job |
|---|---|---|---|
| 01-paginate-off-by-one | easy | python | fix an off-by-one/clamping bug in `paginate` |
| 02-slugify-feature | easy | python | add `slugify` (NFKD, collapse, boundary truncation) |
| 03-extract-helper-refactor | easy | python | refactor duplicated validation into one helper; tests unchanged (AST check) |
| 04-bash-log-summary | easy | bash | top-N client IPs from an access log (status filter, ties, errors) |
| 05-lru-ttl-cache | medium | python | LRU cache with TTL (purge-before-evict, get does not extend TTL) |
| 06-semver-compare | medium | python | semver 2.0.0 precedence incl. prerelease rules and validation |
| 07-event-emitter-reentrancy | hard | node | fix re-entrancy, add/remove-during-emit and once/off bugs |
| 08-dst-business-days | hard | python | business-day arithmetic across DST and local-midnight weekdays |
| 09-pkg-cache-key-bug | hard | python | 3 root causes across `keys.py` and `client.py` (cache keys, input mutation) |
| 10-csv-parser | hard | python | RFC-4180 parser without the `csv` module (differential test vs stdlib) |

### 3.2 Arms

Arm A `--effort high`, arm B `--effort medium`. Identical in everything else: model alias `sonnet`, prompt (task prompt plus one constant suffix: work only inside the cwd, run the visible tests, finish with one sentence), tools `Bash,Read,Edit,Write,Glob,Grep`, `--permission-mode acceptEdits --permission-prompts none`, `--max-budget-usd 2` per run.

Command (stdin carries the prompt): `claude -p --model sonnet --effort <high|medium> --safe-mode --no-session-persistence --output-format stream-json --verbose --include-hook-events --permission-mode acceptEdits --permission-prompts none --max-budget-usd 2 --tools <T> --allowedTools <T>`.

### 3.3 n and schedule

10 tasks x 2 arms x 2 reps = 40 runs. The schedule is deterministic (seed 20261123): per rep a seeded shuffle of the tasks; each (task, rep) is an adjacent A/B pair; the arm order alternates with (task index + rep), so every task runs both orders across its two reps. Never all-A then all-B. At most 3 runs concurrent. Per run: wall timeout 900 s (SIGTERM then SIGKILL, to the process group the runner started only).

### 3.4 Isolation and safety

- Fresh `mkdtemp` git repo per run, copied from `seed/`, committed as `seed`; removed afterwards. The hidden `accept.sh` runs in that repo after the agent exits.
- The child gets a scrubbed environment: only HOME, PATH, TMPDIR, LANG, USER, LOGNAME, TERM, NO_COLOR, PYTHONDONTWRITEBYTECODE and git identity/config-null variables. No `ANTHROPIC_*` (so the run goes direct, not through the local Headroom proxy that this session uses), no `CLAUDE_*` session variables or messaging token. Nothing secret is in argv, env or logs.
- `--safe-mode` disables hooks, plugins, CLAUDE.md discovery, skills, MCP; `--include-hook-events` makes any hook that nevertheless fired visible (recorded as `hook_events`, expected 0). `--bare` is impossible: this account is a claude.ai subscription login (OAuth), and `--bare` reads only API keys. The CLI reads its own login; no credential is read, copied or logged by the runner.
- `--no-session-persistence`: no transcript written. `~/.heimdall` and `~/.claude/settings.json` are never touched by the runner.
- Stop rules: free disk below 10% (checked before every run), the account's 5-hour usage window at or above 90% (read from the CLI's `rate_limit_event`, checked after every run), total spend at or above $60. A stop leaves a resumable partial JSONL; the report then says PARTIAL.

### 3.5 Metrics per run (one JSONL row per attempt, `evals/effort-ab/results/runs.jsonl`)

Output tokens (from `modelUsage`, cross-checked against `usage`), fresh input, cache read, cache write, CLI cost field, `num_turns`, CLI `duration_ms`, runner wall time, thinking-token estimate (CLI event, INF), tool-call counts, hook events, models used, files changed and diff lines, the five-hour window utilization, and acceptance pass/fail with its tail. The final `git diff` of each run is kept in `results/patches/`. Raw streams are gzipped under `results/streams/` (gitignored, local).

### 3.6 Pass, infra failures, retries

Pass = `accept.sh` exits 0 and the run was not an infra failure. A timeout or the per-run budget cap is a model outcome (counted, fail). An infra failure (no `result` event, or `is_error` for any other reason, e.g. API 5xx) is re-run in a fresh repo, at most 2 more attempts; the failed attempt is logged uncounted and its cost is included in total spend. If attempts are exhausted the run counts as a fail and is flagged.

### 3.7 Pre-registered decision (from the brief, unchanged)

**GO for medium as the default** only if ALL hold:
1. Pass rate at medium is at least high's (passes over the 20 runs per arm; zero tolerance), AND no task that passes at high in both reps fails at medium in both reps.
2. Mean output tokens (pooled mean over each arm's 20 runs) drop by 15% or more, medium vs high.

Otherwise **NO-GO**. Fewer than 40 counted runs: INCOMPLETE. Reported alongside, never changing the verdict: paired per-task deltas (the pairing unit is the task), a task-level bootstrap 95% CI of the drop (20,000 draws, seed 12345), an exact two-sided sign test over tasks, and the means of every other metric. `evals/effort-ab/analyze.py` implements this rule and nothing else; `test/effort-ab.test.sh` pins each branch (GO, 10% drop, task regression, one fewer pass, exactly 15%, INCOMPLETE, infra exclusion).

## 4. Known limits (stated before the data)

1. Small n: 10 tasks, 2 reps per cell. A tie in pass rate is a weak statement; at 100% vs 100% the A/B cannot see a quality drop smaller than about 1 task in 10 (ceiling effect). One model (`sonnet` = `claude-sonnet-5-5`), one machine, one account, one day; sampling is not seeded.
2. This is plain `claude -p` in safe-mode, NOT the hmd subagent stack (no `hmd:coder` prompt, no 12.9K-token CLAUDE.md chain, no 7.3K-token skill listing, no hooks). Whether thinking at medium behaves the same under that load is not measured.
3. Tasks are small single-module jobs, the kind the Effort ladder already says to run at low/medium. Multi-file design, security and adjudication work (which the ladder says to leave at default) are not tested, so a GO would say nothing about them.
4. `output_tokens` includes hidden thinking and cannot be split; the thinking estimate is the CLI's own number. The hidden tests are a proxy for quality (no review of style, minimality or readability), only for correctness on the stated spec.
5. Cost is the CLI's list-price-equivalent field on a subscription login, not an invoice. Concurrent runs share a cached prefix, so cost and cache-read means are noisier than token means; output tokens do not depend on cache state and are the primary endpoint.
6. The model's default effort when no flag is given was not verified, so arm A (explicit `high`) equals "current" only if the default is `high`. The 15-25% estimate was "vs current".
7. Concurrency 3 on one machine may inflate wall times (API latency); it cannot change token counts.
8. A real smoke run on a throwaway task (`00-smoke`, medium, not part of the experiment, not in the repo) validated the CLI invocation before any measured run; it is excluded from every number here and nothing in the design changed after it.
