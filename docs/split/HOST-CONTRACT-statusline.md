The contract between the statusline repo (`hmd-statusline`: the HUD renderer, the sigil renderer and their registrars) and its host (`heimdall`, which keeps every host-side file named below). Task T0.3 of `docs/superpowers/plans/2026-11-22-split-skills-statusline-repos.md`, section 1b. T2.2 copies this file into the new repo as `HOST-CONTRACT.md`.

Verified in heimdall `main` @ `100b4513` on 2026-11-22, read-only. Every line number below was found by grep in that tree. The plan's own numbers were re-checked; the ones that drifted are in section 6.

## Notation

- `path:N`, `path:N-M` and `path:N,M` name lines of that file in the tree above. The parenthesised `anchor` after a reference is literal text found on those lines. Re-check one with `sed -n 'Np' path | grep -F 'anchor'` (a range: `sed -n 'N,Mp'`).
- "If absent" columns are read from the code, never run. Plan section 5 descopes "standalone statusline on a machine with no hmd" (expected-red if tried), so no fail-open behaviour below is measured.
- IDs: O = host entry point the moved code calls or loads. F = host-written file the moved code reads. W = file the moved code writes. I = host code that runs, loads or matches a moved file.

## 1. Resolution rule: host code is found by relative path

The moved code finds the host through its own location. Host entry points therefore sit in the same `bin/` and `bin/lib/` as the moved `bin/heimdall-statusline`; this is why the plan keeps a path-identical mirror in heimdall. A standalone clone has an empty host `bin/`, so every row of section 2 is a call into a missing file there.
