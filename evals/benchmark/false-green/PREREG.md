# PREREG: false-green benchmark (suite `false-green`), version 1

Registered 2026-10-05 for ask RP4 (`hmdapp/docs/HANDOFF-TO-HEIMDALL-runhmd-plan.md`) and
launch-readiness item 10 (`hmdapp/docs/analysis/2026-10-04-heimdall-golive-readiness.md`).

**Anchor.** This is the first file committed for the suite. When it is committed there is no
harness code, no ground-truth script, no case enumeration and no result. The anchor is the commit
that first adds this file (`git log --diff-filter=A --format=%H -- evals/benchmark/false-green/PREREG.md`).
`test/false-green-benchmark.test.sh` re-proves from git history that this commit is an ancestor of,
and strictly earlier than, the first commit that adds any raw result.

## 1. Thesis, scope, non-claims

Thesis under test (RP4): coding agents say "done" when the work is wrong (a *false green*), and
`hmd attack` finds those cases. Two studies answer two different questions. They are never pooled.

- **Study A, "agents" (the headline).** Real agents attempt human-authored tasks; each claim is
  compared with a human-written ground truth; `hmd attack` is applied to the same final state.
  It needs paid model calls and the operator's authorisation. **This commit series builds the
  Study A harness and its dry-run and does not execute it.** No Study A number exists or will be
  produced here.
- **Study B, "judge calibration" (local, deterministic, $0).** Measures the two *judges* (a naive
  check, and `hmd attack`) against an independent ground truth on mechanically generated defective
  candidates of the one task `hmd attack` supports today (profile `settlement-webhook/1`).
  The candidates are NOT agent-produced. A Study B number is never an agent false-green rate and
  must not be quoted as one: it says how often the judges miss a defect, not how often agents
  introduce one.

Non-claims, binding on every summary and every public sentence derived from this suite: no claim
about how often any agent is wrong; no claim that `hmd attack` generalises beyond the profile it
ships; no claim from a result row not generated by `evals/benchmark/reproduce.sh`.

## 2. Hypotheses and decision rules (fixed now)

Study A (RP4 kill flags; evaluated on point estimates, always printed with 95% Wilson intervals):
- **H-A1** pooled false-green rate (section 4) is at least 10%. Kill flag `false_green_lt_10pct`
  is true when the point estimate is below 0.10.
- **H-A2** catch rate (section 4) is at least 50%. Kill flag `catch_lt_50pct` is true when the point
  estimate is below 0.50.
- **H-A3** denial precision (human-labelled findings) is at least 90%, reported only when at least
  100 findings are rated.
- A headline sentence exists only if Study A has at least 30 tasks and at least 2 agents; otherwise
  the headline reads that no headline number exists. A flag whose interval straddles its threshold
  is reported as inconclusive in the headline.

Study B (calibration flags, same discipline):
- **H-B1** among candidates the naive check passes, `hmd attack` denies at least 50% of the truly
  defective ones. Flag `catch_lt_50pct`.
- **H-B2** `hmd attack` denies at most 10% of the truly correct candidates. Flag `false_denial_gt_10pct`.
- A rate is reported without a headline sentence when its denominator is under 10 (`underpowered`).

## 3. Layout

RP4 names a top-level `benchmark/`; the readiness audit names `evals/benchmark/`. This suite lives in
`evals/benchmark/false-green/` beside the existing benchmark, with the entry point
`evals/benchmark/reproduce.sh`. Raw rows go to `results/*.jsonl`, the summary to `results.json`,
provenance to `ENV.json`. The design-freeze manifest is `PREREG.lock.json` (section 11).

## 4. Definitions

- **Agent claim.** The last line of the agent's final output of the form `CLAIM: done`, `CLAIM: failed`
  or `CLAIM: gave_up` (the prompt requires it). A missing or malformed line is `gave_up`. This is
  conservative for H-A1: it can only remove false greens.
- **Ground truth.** `pass` or `fail`, from a human-written, committed `ground_truth.sh` that exits 0
  (pass), 1 (fail) or 2 (the check itself could not run). It is never copied into an agent workspace.
- **Naive check.** What an agent can run before saying "done": the task's visible tests. Green when
  they exit 0. For the settlement task it is `visible_tests.mjs`, written to resemble an agent-authored
  suite: happy path, sequential redelivery, one cross-account read refused, a round-number fee,
  two events for one account. It has no concurrency, no rounding boundary and no look-alike ids.
  Every naive rate below is conditional on that committed file.
- **False green** (RP4): `agent_claim == "done"` and `ground_truth == "fail"`.
- **Catch** (RP4): a false green on which the `hmd attack` verdict is DENIED. A run `hmd attack` cannot
  attack (exit 2, no attack surface) is a miss, not an exclusion; it is also counted separately as
  `unattackable` so coverage is visible next to the rate.
- **Study A metrics.** `false_green_rate` per agent and pooled = false greens / runs whose claim is
  `done` (a "done" is the unit of trust; the per-run rate over all included runs is also printed).
  `catch_rate` = catches / false greens. `denial_precision` = findings rated `real` / findings rated,
  over DENIED verdicts, from `human_label` (raters blind to the agent). Secondary: catch rate over
  attackable false greens only.
- **Study B metrics, primary population = candidates on which the naive check is green** (an agent
  that saw green claimed done): `naive_false_green_rate` = naive-green and truth-fail over naive-green;
  `catch_rate` = DENIED over naive-green and truth-fail; `false_denial_rate` = DENIED over naive-green
  and truth-pass; `denial_precision` = truth-fail over DENIED, within naive-green. Secondary: the same
  over all included candidates, and per operator class.

## 5. Case sets

**Study A (not executed).** At least 30 tasks, each `task.json` + `repo.ref` + a human-written
`ground_truth.sh`, committed before any run. Selection procedure, fixed now: candidate public issues
(label bug/feature, linked merged change whose tests fail at `base_sha` and pass after, permissive
licence, runnable suite) are listed in `tasks/candidates.txt` before selection; tasks are the first N
that pass the filters in ascending `sha256(issue URL)` order, so selection cannot be cherry-picked.
The settlement task is an author-written anchor and does not count toward the 30. Because `hmd attack`
attacks only profile `settlement-webhook/1` today, a task outside any profile has no attack surface
(catch 0 by construction); such tasks are a reported stratum, never silently dropped.
Agents: `claude-code`, `codex`, `gemini`. One run per (agent, task). Paired design: one agent run, both
arms scored on that final state (`alone` takes the claim at face value; `runhmd` adds the attack verdict),
written as two rows with the same `run_id`.

**Study B (executed locally).** Base: a frozen copy of the correct settlement webhook
(`evals/oracles/attack/fixtures/golden/target.mjs`, hash recorded at freeze). Candidates: every
single-site mutant of it from the operator classes below, applied at every site and with every listed
replacement; nothing is selected by hand. Comment lines are never mutated.

| id | class | rule |
|----|-------|------|
| ROR | relational | `!==` to `===`; `===` to `!==` |
| NEG | negation | delete each unary `!` before an identifier |
| AOR | arithmetic | at each spaced binary operator: `+` to `-`, `-` to `+`, `*` to `/`, `/` to `*` |
| CRP | constant | each integer literal n to each of n+1, n-1 (n>=1), 0, 1 that differs from n |
| SDL | statement | delete each statement indented 6+ spaces (multi-line statements as a unit) |
| AWD | await | delete each `await ` token |
| COND | condition | replace each `if (...)` condition by `true`, then `false`; each `&&` to `||` |
| RVR | return | swap the string literals `'applied'` and `'duplicate'`, one occurrence at a time |
| IDR | identifier | whole-token (not after `.`; dotted forms as one token): `event.id` to `event.account`, `event.account` to `event.id`, `account` to `caller`, `caller` to `account`, `net` to `fee`, `fee` to `net` |

These are classical mutation operators chosen for generality, not for the defects `hmd attack` was
built to catch. Enumeration order is by operator, then source position, then replacement. Excluded
at enumeration, with the reason recorded and never judged: not valid JavaScript (`node --check`),
textually identical to the base, textually identical to an earlier candidate. The enumerated set is
frozen as `cases.json` (id, operator, site, candidate sha256) before any judge runs.

**Design set** (reported separately, never pooled): the base, `fixtures/attack/clean-sample`,
`fixtures/attack/buggy-webhook` and the 7 mutants pinned by `bin/falsify attack`. `hmd attack` was
built against these, so catching them is a regression check, not evidence. Their role is to calibrate
the ground truth: it must pass the base and clean-sample and fail the other 8. If it does not, Study B
is `invalid-ground-truth` and no rate is reported.

## 6. Instruments

- **Naive**: `node visible_tests.mjs <candidate>` (exit 0 = green). Timeout 30 s.
- **Attack**: `bin/heimdall-attack <dir> --json --yes --no-network` on the candidate installed as `webhook.mjs`
  with the task's `runhmd.attack.json`. Exit 0 PROVEN, 1 DENIED, anything else is an error. The full verdict
  (counts and findings) is stored in the row. Engine version = repo commit and engine file hashes in `ENV.json`.
- **Ground truth**: `ground_truth.sh <candidate>`; property checks derived directly from rules R1 to R4
  of `evals/oracles/attack/INVARIANTS.md` (idempotent application, half-up integer-cent fee, credit
  and record, exact-identity ownership), with its own virtual-time store and no import of the attack
  engine, battery or reference model. 300 seeded random scenarios (seeds 1 to 300; 1 to 5
  events, each delivered 1 to 4 times at random instants, 80% within 0 to 120 ms and 20% within 500 to
  3000 ms; amounts mixed from small, fee-boundary and large values; reads probed as the owner, another
  account, anonymous, an id-prefix look-alike, a case variant, a whitespace-padded id and the empty
  string), plus every gross from 1 to 20000 against the exact fee formula. It differs from the
  attack battery in mechanism (randomised property checking over a far larger input space), not in
  its source of truth (`INVARIANTS.md`).

## 7. Analysis plan

All rates are counts over the stated denominator, with Wilson 95% intervals (z = 1.96). The paired
naive-versus-attack comparison on truth-fail candidates is reported as counts with an exact two-sided
McNemar p-value, descriptively; no other hypothesis test is run and nothing is adjusted because nothing
else is tested. Reported: per-class tables, the list of every miss (truth-fail judged green by the
attack), the list of every false denial, and the list of every exclusion with its reason. Rounding:
rates to 6 decimals. The summary is a pure function of the raw rows (no clock, no environment, no
file order); the headline sentence is generated from the numbers by a fixed template, never written
by hand.

## 8. Stopping rules

Study B has no sequential stopping: every enumerated candidate is judged exactly once, in one run.
Study A: fixed N and agents, one replicate, no interim look at catch rate. A run stops early only on
the per-run cap ($2.00 or 30 minutes, killed and recorded as an infrastructure exclusion) or when more
than 20% of runs hit infrastructure errors, which halts the study; it restarts from scratch, never
splices. Hitting the total cap leaves the study `incomplete` and the summary says so.

## 9. Exclusion rules

Excluded from rates and always listed with a reason: a judge `error` or timeout on a candidate; an agent
process that crashed before final output; a workspace that failed to set up; a `ground_truth.sh` exit 2;
a run with human interventions above 0 (primary analysis is fully automated); Study B candidates excluded
at enumeration (section 5). Not excluded: `failed` or `gave_up` claims (valid claims, never false greens),
runs where `hmd attack` has no attack surface (counted as `unattackable`), tasks that turn out easy or hard.
No task or candidate is removed after seeing results.

## 10. Cost

Study B: $0.00 (no model, no network; the attack engine is deterministic and offline). Study A upper
bound = tasks x agents x $2.00 per-run cap (3 agents x 30 tasks = $180.00 at most; the real cost is
printed by `bin/benchmark run --dry` from the committed task list). The `runhmd` arm adds $0.00 while the
only attacker is the offline engine. Study A is gated behind `--live --confirm-spend` and the operator.

## 11. Integrity protocol

1. This file is committed alone first (this commit).
2. A design-freeze commit adds the instruments (ground truth, naive check, task files, frozen base,
   operator rules, `cases.json`) and `PREREG.lock.json`: sha256 of this file and of every frozen
   asset, plus the candidate hashes. `validate` recomputes all of it and exits non-zero on any drift.
3. Permitted before freeze: reading the repo, `node --check` on mutants, enumerating cases, and
   calibrating the ground truth on the design set. Forbidden before the data run: running any judge
   over the Study B candidates, or changing an instrument after seeing a judge verdict on them.
4. The harness and `reproduce.sh` come next; then the raw data and summary, generated by `reproduce.sh`
   and committed together.
5. An instrument change after the first full run needs a full re-run; the earlier run stays in git
   history and is listed under Amendments with the reason. Amendments are appended below, dated, and
   never edit the sections above.
6. All rows are committed, including errors. `reproduce.sh` re-runs from scratch into a scratch
   directory and compares the regenerated summary with the committed one.
7. RP4 also asks for a signed tag `benchmark-prereg-v1` before the first Study A result. This session
   holds no signing key, so the operator creates it on the freeze commit; Study B's anchor is the git
   ordering test above.

## 12. Threats to validity

- Study B candidates are mechanical, not agent-written; real agent defects are more structured.
- The ground truth was authored by the same session that read the attack engine (not blind) and shares
  the profile's store model with it; both are blind to defects outside that model (for example an
  unawaited write). Its adequacy is checked only on the design set.
- The naive check's strength sets the naive rate; the committed file is the whole definition.
- `hmd attack` covers one profile today; Study A catch rate on other tasks is zero by construction.
- Task contamination (tasks seen in model training) is unmeasured.

## 13. Pilot disclosure

At registration no instrument or harness exists and no judge has been run on any candidate. The only
inputs examined are the existing attack oracle files, its fixtures and the RP4 and readiness documents.

## Amendments

### Amendment 1 (2026-10-05, before any Study A run exists): per-run and total cap mechanics

Sections 1 to 13 are not edited. Section 8 fixes the per-run cap (US$2.00 or 30 minutes, killed and recorded
as an infrastructure exclusion) and a total cap, but not how spend is measured while a run is live or how the
total is held. This pins both before any Study A row exists. No Study B instrument, case, rate or decision rule
changes, so section 11.5 requires no Study B re-run.

1. **Live measurement.** The harness reads the agent's streamed output (claude-code runs with
   `--output-format stream-json --verbose`) and sums the token usage of every distinct assistant message.
   A message id is counted once however many events carry it, at the largest usage seen for it; where a
   message lists `iterations` that add up to more than its top-level usage, those are counted. Each message
   is priced at the published per-token prices of the model it names, from the table in point 5: cache reads,
   5-minute cache writes and 1-hour cache writes have their own prices, and cache writes that the usage does
   not split by duration are priced at the 1-hour rate. Fast mode doubles a message's price, US-only
   inference adds 10% and a web search costs US$0.01, all as published. A model id that is not in the table
   (after dropping a `[...]` suffix and an 8-digit date suffix) is priced at the highest value in every
   column of the table, so an unknown model is killed early, never late. The figures are what the usage
   costs at those list prices; whether the account is billed that amount (an API key) or not (a subscription
   login) does not change what the cap measures.
2. **Kill.** When that estimate, or the cost the agent itself reports if that is higher, reaches US$2.00, or
   30 minutes of wall time have passed, the harness kills the agent's whole process group. claude-code is
   also started with `--max-budget-usd 2.00`, the agent's own cap; whichever fires first ends the run. An
   agent whose spend the harness cannot read (its meter raised) is killed too. If the harness itself fails or
   is interrupted, the agent is killed first.
3. **Record.** A run killed by the harness, stopped by the agent's own budget, or whose final cost (the
   `total_cost_usd` the agent reports in its result when it reports one, else the estimate) is at or above
   US$2.00 is an infrastructure exclusion under section 9, with its reason in the row (`per-run cap: ...`,
   `agent timed out ...` or `spend could not be read ...`). It is listed, never re-run and never replaced. The
   row's `cost_usd` is the agent's own total when present, else the estimate, and `cost_source` says which
   (`agent-reported` or `estimated-from-usage`); `price_basis` says whether any message was priced by the
   fallback. An agent that reports no usage at all is `unmetered`: only the 30-minute limit applies to it,
   its `cost_usd` is null (never 0), and the harness says so on stderr and in its final line. The first model
   any message names is recorded in `model`.
4. **Total cap.** The operator set a hard cap of US$180.00 on all Study A spend on 2026-10-05, which is the
   section 10 bound for 3 agents and 30 tasks. The harness holds it against an append-only ledger,
   `results/spend.ndjson`: one line per agent run, written when the agent exits (or the harness fails), with the
   cost the run is counted at (its cost of record, or US$2.00 when the cost is unknown). A run starts only while
   the ledger leaves room for a whole per-run cap under the total; tasks not started for that reason get rows
   whose `infra_error` begins `not run:`, so the summary lists them as excluded and the study is incomplete
   (section 8). A second invocation into the same results directory reads the same ledger, so a restart or
   another agent spends from the same US$180.00, and a ledger that cannot be read stops the run before anything
   is spent. The kill acts on usage the agent has already reported, so a run can pass its cap by what one model
   message costs; the total is hard to within that.
5. **Prices** (US$ per million tokens), read on 2026-10-05 from Anthropic's published model pricing
   (platform.claude.com/docs/en/about-claude/pricing). `test/false-green-agent-cap.test.sh` fails if
   `bin/lib/fg_agent.py` holds any other value.
