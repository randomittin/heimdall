## 2026-09-04T07:01:55Z — [COMMUNICATION] docs(heimdall): claude-mem is retired, not merely unqueried

agents/heimdall.md still asserted 'claude-mem itself stays installed and
its passive injection is unaffected — only the active per-task query
mandate is removed.' That went false when the retirement migration
landed, and a doc asserting old behaviour beside new code is exactly the
drift this repo keeps getting bitten by.

The trigger was not the 0% usage figure alone. claude-mem's own
UserPromptSubmit hook was observed BLOCKING an operator's prompt --
'claude-mem worker unreachable for 5 consecutive hooks' -- so it fails
CLOSED on a strictly optional dependency. That is the inverse of this
repo's rule that hooks exit 0 and fail open precisely so a broken
accessory can never wedge a session.

Records that the scrubber is deliberately KEPT and no-ops when claude-mem
is absent: hmd cannot guarantee the plugin is gone from someone else's
machine (HEIMDALL_KEEP_CLAUDE_MEM=1, or they have not re-run install.sh),
so deleting a privacy control while the thing it protects may still run
would be a security regression.

Historical cost figures left intact — they are the evidence, not stale.
