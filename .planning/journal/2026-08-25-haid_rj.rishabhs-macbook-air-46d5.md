## 2026-08-25T02:57:43Z — [COMMUNICATION] docs(agent-resume): correct the network->pressure rationale, pin it with a test

46f593f left `network` unwired to the pressure controller and recorded the
reason as "it would need its own exactly-once marker". THAT REASON WAS WRONG,
and this corrects the repo's own history rather than leaving a plausible-
sounding but false claim in it.

_classify_cause's if/elif chain yields exactly ONE class per death, and
RESUME-ATTEMPTS.json is keyed by worktree HEAD and already shared between the
overloaded and network paths. A `cls == network && attempts == 1` gate would
key off that same file with no collision against the overload gate. No new
marker was ever needed. Verified by mutation, not by reading: widening the
guard to include network made exactly the expected assertion fail, proving the
mechanism works — then reverted.

THE REAL REASON network stays unwired is signal quality, not mechanism.
pressure_control.record_event() feeds connection_reset and overloaded_error
into the IDENTICAL AIMD window with ZERO per-kind weighting. An overload marker
(529/429) requires a completed HTTP round-trip in which the remote server
itself signalled distress. A network marker (econnreset/etimedout/getaddrinfo/
dns failure) is what the OPERATOR'S OWN wifi, VPN, or a sleeping laptop
produces, with no server involvement at all. hmd spawns up to 10 agents from
one machine over one shared link, so a single local blip trivially hits 3+
agents at once and satisfies threshold()=3 "for real" while carrying zero
API-capacity signal. That inverts what the threshold exists to filter —
correlation across agents hitting the same REMOTE backend, not the same LOCAL
link — and would let a routine wifi drop trigger a genuine spurious throttle.
A spurious throttle is worse than no signal.

The decision is now pinned by a falsifier rather than left to prose: the new
part-2/2 fixture uses a REAL worktree to reach the exact attempts==1 boundary
that fires the overload path, so a future "just add network too" change fails
a test. The pre-existing part-1/2 case only exercised the weaker no-worktree
(attempts=null) path, which the mutation test proved does NOT catch that
regression.

No logic changed — the overloaded-only gate is untouched.
test/heimdall-agent-resume-pressure.test.sh 24/24 (21 + 3 new),
heimdall-agent-resume 62/62, both verified on main after the carry.

Known, pre-existing, NOT introduced here: the shared attempt counter means
whichever of overloaded/network occurs first at a fresh HEAD claims the
attempts==1 slot, so a second death of the other class at the same stuck HEAD
is skipped. Present in 46f593f already; worth knowing if the counter design
changes later.

## 2026-08-25T03:11:42Z — [COMMUNICATION] feat(pressure): add heimdall-529-scan, a read-only transcript overload detector

REFUTES A DOCUMENTED CEILING. bin/lib/pressure_control.py and
bin/heimdall-agent-resume both state that hmd "cannot see the harness's HTTP
responses" and learns of overload only from an agent's own death message. That
is true for LIVE requests. It is FALSE for what Claude Code records: its own
session transcripts carry the API error as STRUCTURAL JSON, not prose.

Measured against this repo's own 118 transcripts: 72 records with
isApiErrorMessage=true, of which 52 are {"error":"rate_limit",
"apiErrorStatus":429} and the remainder include real
{"error":"server_error","apiErrorStatus":529} entries. isApiErrorMessage
(bool), apiErrorStatus (int|null) and error (closed string enum) are keys
Claude Code itself writes — the human-readable "API Error: 529 Overloaded"
sentence in message.content[0].text is incidental and nothing here parses it.
So this is stable-field detection, not a regex over prose, which is the
distinction that decided it was worth building at all.

Every record is timestamped, so the scan is windowed rather than re-reading
history: a file whose mtime predates the cutoff is skipped unopened.

DELIBERATELY READ-ONLY. It does NOT call heimdall-pressure record. Emitting a
count a caller may act on is a materially safer contract than mutating AIMD
state from a scanner that could be run twice — a double-run would otherwise
manufacture a threshold breach out of one real event. Stated in the file
header.

Never-fail contract matching heimdall-metric/heimdall-pressure: a missing
transcript dir, an unreadable file, or a malformed JSON line degrades to an
empty result at exit 0. --strict is opt-in for a bad --since.

test/heimdall-529-scan.test.sh 13/13, hermetic against constructed fixtures —
never the operator's real transcripts, which would be non-reproducible and
could leak session content into test output. Includes the negative cases: a
transcript with no overload records yields zero, a malformed line does not
crash, and an out-of-window record is excluded.

FOLLOW-UP NOT DONE HERE: the "cannot see HTTP responses" wording in
pressure_control.py and heimdall-agent-resume is now too strong and should be
narrowed to LIVE requests. Left for a separate commit so this one stays
reviewable.
