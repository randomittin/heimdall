## 2026-08-23T04:37:50Z — [COMMUNICATION] Merge branch 'worktree-agent-a9e8c2f7ade79ea76' — reconnect the /hmd:maintain seek-then-fix loop

One label set severed the pipeline. seeker filed issues as 'bug,seeker'; the engine's
sync_queue_from_github requests only 'maintainer' (DEFAULT_MAINTAINER_LABEL). gh's
--label filter is a SUPERSET/AND match, not OR, so the two sets never intersected and a
seeker-filed issue was never once ingested. That is why both halves of /hmd:maintain
measured zero spawns across 432 agent calls — not disinterest, a broken connection.

Fixed on the seeker side rather than by widening the engine filter, and the reasoning
matters: 'bug' already caps severity at high (never critical), so auto-ingest does not
newly trigger the approval-park gate, and the fixer's hard PR-not-merge boundary keeps a
human reviewing before anything lands. The routing matrix is severity x confidence with
no origin gate, so auto-ingest is the intended design, not something needing a manual
promotion step.

The regression guard is the valuable part: a label-aware fake gh (the shared fake ignores
--label entirely, which is exactly how this went unnoticed) pins that the historical
bug,seeker set ingests 0.

Conflict resolution note: both this branch and an earlier merge corrected the same false
'normalized by issue_queue' claim in commands/maintain.md. Kept main's wording, and fixed
a contradiction the branch left behind — it still told readers a seeker-filed issue is
'not automatically picked up' and pointed at a manual workaround, which its own fix had
just made false.

## 2026-08-23T04:59:47Z — [COMMUNICATION] fix(test): stop guessing heimdall-route's fixture ports from PID

BASE_PORT=$((26000 + ($$ % 4000))) guessed into a fixed, narrow,
guessable 4000-port range with zero collision detection or retry, then
derived all four ports the suite needs (two live fixture proxies, two
"must stay unused" checks) from it.

Freshly reproduced today: predicting a target run's BASE_PORT from its
PID and squatting an unrelated process on that exact port alone
cascades a clean run to "10 passed, 5 failed" (exit 1) — indistinguishable
from a real code defect in the sweep's report.

Fix: ask the OS for four free ports (bind each to port 0, read back
getsockname(), close), all four bound simultaneously in one interpreter
so this run can never collide with itself. Falsified fresh:
  - RED:   PID-predicted port squatted externally -> 10 passed, 5 failed
  - GREEN: fixed code, same hostile environment but with the OLD
           scheme's entire 26000-27999 half-range externally occupied
           (2000 ports) -> 19 passed, 0 failed
  - GREEN: fixed code, clean environment -> 19 passed, 0 failed

Note: this was not the cause of the sweep's originally reported FAIL
(that was bin/hmd corrupted to a dangling symlink in a different
checkout, per orchestrator). It is a separate, independently
demonstrated hazard of the same class as the heimdall-watch fix
(df185a1) — a collision-prone fixed/derived resource path — worth
closing under jobs=6 parallel execution regardless.

## 2026-08-23T05:49:52Z — [COMMUNICATION] fix(dream-bundle): stop telling users a folder grant lapsed when it did not

The identity-change notice said flatly that "a Full Disk Access grant made against the
old binary no longer applies". True for FDA, which keys on code identity — and wrong
about the grant this subsystem actually depends on.

Measured today by rebuilding with the new icon: the cdhash moved
17bc6912 -> c01c9d10, and the nightly job stayed green with the existing grant
untouched.

  Identifier=dev.runheimdall.hmd-dream
  CandidateCDHash sha256=c01c9d10...
  TCC (user db): dev.runheimdall.hmd-dream|2      <- still allowed
  {"ts":"2026-08-23T05:31:35Z","result":"ok"}     <- fresh launchd-side run

A FOLDER service grant (Downloads/Documents/Desktop) keys on the BUNDLE IDENTIFIER, so
it survives a content change that moves the hash. That distinction matters: the repo
spent 41 days asking for Full Disk Access when a folder grant was what the job needed,
and a warning that conflates the two would push people back toward the broader
permission for no reason — or scare them into re-granting something that never lapsed.

Determinism is still the reason the notice exists at all, and it still fires when the
identity really does move. This only scopes the consequence to the service it is true of.
