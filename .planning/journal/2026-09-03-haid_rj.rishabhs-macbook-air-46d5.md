Two defects found after the operator uninstalled the external caveman
plugin and restarted.

1. SessionEnd "Hook cancelled". The hook's own _hmd_to() wrapper reads:
     if command -v timeout ...; elif command -v gtimeout ...; else "$@"
   Measured on this machine: BOTH are ABSENT. macOS ships neither, so the
   final branch ran every command with NO timeout at all — the advertised
   10s cap has never once applied here, and the harness killed the hook
   when the unbounded work overran its budget.

   Adds a `perl -e 'alarm 10; exec @ARGV'` branch before the bare
   fallback, which is this repo's own documented convention for exactly

   rc=142 after ~10s instead of running to completion.

   Step timings measured before the fix (100 worktrees in this checkout):

   verify-edits --quick 0.4s. Nothing was reordered or dropped — the
   checkpoint write is the resume contract and stays first.

2. Divergence warning fired forever on an orphaned file. Uninstalling the
   plugin removes the marketplace entry but leaves BOTH
   ~/.claude/plugins/cache/caveman AND ~/.claude/.caveman-active behind,
   the latter still reading "full". _warn_if_diverged() keyed only on that
   flag's content, so every `get` warned about a plugin that no longer
   exists. Noise is how real warnings get ignored — measured repeatedly in
   this repo.

   warning when the registry is unreadable: a missing registry is not
   evidence of absence, and suppressing a real divergence is worse than
   one spurious line.

   The check is NOT removed. It still catches the behaviour that made hmd
   take ownership — the plugin rewriting its own flag to "full" while
   live. Red-proofed: with a registry naming caveman it still warns; with
   an empty registry it is silent; with an unreadable path it warns.

## 2026-09-03T10:10:49Z — [COMMUNICATION] feat(install): an update RETIRES the legacy external caveman plugin

Other users who installed hmd before compression moved in-house still
have the plugin, because hmd itself installed it. Confirmed from history
(pre-599e778 bin/heimdall):
    claude plugins marketplace add JuliusBrussee/caveman
    claude plugins install caveman@caveman

Leaving it is actively harmful, not merely redundant: BOTH now inject a
compression instruction at levels that disagree. The plugin resets ITSELF
to "full" on restart -- the documented defect that caused the move -- while
hmd holds "ultra". Two conflicting instructions are worse than either
alone, and they silently invalidate any compression measurement taken
afterwards. Measured on this machine: removing the marketplace left the
cache dir AND .caveman-active (still reading "full") behind, so residue
survives a manual uninstall too.

install.sh is the atomic unit of apply, so the retirement rides every
update automatically. Scoped tightly and reversibly:
  * targets caveman@caveman and the JuliusBrussee marketplace EXACTLY --
    never a wildcard, never another plugin;
  * marketplace removal is GUARDED by a post-uninstall re-check, because
    removing a marketplace another plugin still needs breaks its updates;
  * fast no-op ("absent") once done -- the steady state stays cheap;
  * HEIMDALL_KEEP_CAVEMAN_PLUGIN=1 opts out for anyone who genuinely
    prefers upstream to hmd's in-house level;
  * NON-FATAL and fail-open: a failed uninstall prints the exact manual
    command and never breaks an update.

Announces on success, and on failure prints the one command to fix it, so
this is never a silent config change behind the operator's back.

test/caveman-plugin-retire.test.sh, 8 assertions: definition present, and
CALLED (a defined-but-uncalled function is the dead-on-arrival class this
repo keeps catching); absent -> absent; opt-out -> kept; no claude CLI ->
skipped, never fatal; exact-id targeting; guarded marketplace removal.
Behaviour cases drive the REAL function through a stub claude on PATH, so
no real plugin state is touched. B3 verified to test genuine absence, not
