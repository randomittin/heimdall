## 2026-09-03T09:57:00Z — [COMMUNICATION] fix(hooks,caveman): SessionEnd timeout never applied; divergence warned on a dead plugin

Two defects found after the operator uninstalled the external caveman
plugin and restarted.

1. SessionEnd "Hook cancelled". The hook's own _hmd_to() wrapper reads:
     if command -v timeout ...; elif command -v gtimeout ...; else "$@"
   Measured on this machine: BOTH are ABSENT. macOS ships neither, so the
   final branch ran every command with NO timeout at all — the advertised
   10s cap has never once applied here, and the harness killed the hook
   when the unbounded work overran its budget.

   Adds a `perl -e 'alarm 10; exec @ARGV'` branch before the bare
   fallback, which is this repo's own documented convention for exactly
   this gap. Verified binding: `sleep 30` through the wrapper now returns
   rc=142 after ~10s instead of running to completion.

   Step timings measured before the fix (100 worktrees in this checkout):
   heimdall-checkpoint write 3.9s, parallelism-tracker grade 0.2s,
   verify-edits --quick 0.4s. Nothing was reordered or dropped — the
   checkpoint write is the resume contract and stays first.

2. Divergence warning fired forever on an orphaned file. Uninstalling the
   plugin removes the marketplace entry but leaves BOTH
   ~/.claude/plugins/cache/caveman AND ~/.claude/.caveman-active behind,
   the latter still reading "full". _warn_if_diverged() keyed only on that
   flag's content, so every `get` warned about a plugin that no longer
   exists. Noise is how real warnings get ignored — measured repeatedly in
   this repo.

   Now gated on Claude Code's own installed-plugin registry
   (plugins/installed_plugins.json), which an uninstall actually clears,
   rather than on files an uninstall leaves behind. Fails OPEN toward
   warning when the registry is unreadable: a missing registry is not
   evidence of absence, and suppressing a real divergence is worse than
   one spurious line.

   The check is NOT removed. It still catches the behaviour that made hmd
   take ownership — the plugin rewriting its own flag to "full" while
   live. Red-proofed: with a registry naming caveman it still warns; with
   an empty registry it is silent; with an unreadable path it warns.
