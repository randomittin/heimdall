## 2026-08-28T11:26:22Z — [COMMUNICATION] fix(fallback): probe the gateway over HTTP, not bare TCP

`check` printed [OK] endpoint_reachable while every real call to the
gateway timed out. The probe did a bare TCP connect, and a wedged server
-- or a webpack dev server still compiling the route, which is what
OmniRoute actually is here -- completes the handshake while never
answering a single HTTP request. So the one check whose entire job is
"can we route to this thing" was structurally incapable of failing for
the most likely way it breaks.

Send a real request and require response HEADERS back. Any status counts
as alive: 307/401/404 all prove something is serving. The probe answers
"is anything answering HTTP here", never "is this authorized", so it is
sent UNAUTHENTICATED -- which also means a liveness check never puts the
gateway token on the wire.

Fails closed, and bounded by HEIMDALL_FALLBACK_PROBE_TIMEOUT (default
3s). The tight budget is deliberate: this is a routing gate, so a
gateway that cannot answer a loopback request in that window is not a
usable fallback and refusing to route is the correct verdict.

Tests 85a-c/86 are falsifiable both ways -- a probe hardwired to False
passes the wedged case alone, so 200/401/307 must also assert reachable.
Verified the old TCP-only logic returns True for both the wedged fixture
and the live gateway, i.e. it fails the new test.

test/heimdall-fallback.test.sh: 136 passed, 0 failed.
