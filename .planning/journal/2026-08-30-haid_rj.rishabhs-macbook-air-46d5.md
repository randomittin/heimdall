## 2026-08-30T08:12:46Z — [COMMUNICATION] fix(watchdog): preserve on the BROAD signal, not the interrupted list

First real use missed its case: a turn-limited agent with 1 uncommitted
file was invisible, because detection iterated only heimdall-agent-resume's
rows and that tool lists only agents recorded as INTERRUPTED. Turn-limit
stops are not recorded there -- so the watchdog covered the case that must
NEVER be auto-retried (quota) and missed the most common case that SHOULD
be resumed (turn limit, 40 this session). Backwards.

Adds 'sweep': any .claude/worktrees/agent-* holding uncommitted changes is
preserved, whatever the recorded reason. Detection breadth and
classification breadth are different problems and are now split --
preserving is additive and non-destructive so it takes the broadest
signal (over-preserving costs one commit; under-preserving loses work
permanently), while classification stays narrow and keeps driving retry
decisions from the recorded reason. Sweep makes NO retry recommendation.

LIVENESS IS A HEURISTIC, documented as one: in-process agents have no
per-spawn OS pid, so there is no liveness proof available. Sweep uses a
conservative staleness window (HMD_WATCHDOG_STALE_SECS, default 600s,
matching the harness stall watchdog) and skips anything modified more
recently. A sibling task shipped pid-less pool entries by assuming a
liveness signal existed today and wedged the tool; this does not repeat
that.

MEASURED on the real machine: 55 agent worktrees were carrying
uncommitted work. 'run' saw none of them. 'sweep' found all 55, preserved
21, and correctly skipped 34 as possibly-live.

## 2026-08-30T13:15:34Z — [COMMUNICATION] fix(delivery-audit): stop manufacturing a false reachability edge to heimdall-task

The reachability gate went RED with "EXEMPTION ROT: STALE heimdall-task
now reachable from a live entry point — remove the exemption". It was
not: delivery-audit only NAMES heimdall-task (in printf labels, and as
an argument to `deadcode --why`) and never executes it. The engine
tokenizes on whole names and cannot distinguish "cites this name" from
"invokes it", so a static literal invented an edge.

Taking the gate's suggestion would have been the wrong fix: removing a
still-needed exemption lets genuinely dead code through, and
false-REACHABLE is the dangerous direction by the engine's own docs
(dead code silently passing) versus false-DEAD, which is a loud
reviewable alarm.

Fixed by assembling the name at runtime from individually non-matching
fragments — the convention this repo already uses for gitleaks fixtures
(docs/superpowers/specs/heimdall-fixture-secret-convention.md). Comment
references are left alone; the tokenizer strips # comments for shell.

heimdall-task now correctly reads DEAD again, its exemption stays
load-bearing, and the tool reports that fact to the operator rather than
hiding it.

Found by the agent that built the tool, which flagged the false edge in
its own report rather than letting the gate be silently weakened.

## 2026-08-30T17:07:01Z — [COMMUNICATION] docs(analysis): caveman upstream — mechanical compression falsifies my general claim

Salvaged from a research agent that died to context thrashing after
writing this into the MAIN checkout (it was spawned as general-purpose,
which gets no worktree isolation — orchestrator error; it tripped the
sweep's tree-integrity check, which correctly flagged it).

THE CORRECTION, and it matters: I have repeated all session that "a hook
injects text; it cannot rewrite model output" as though it were a general
limit. It is not. It is true for the HOOK path — hmd's installed plugin,
and the MIT skill hmd vendored — and false for upstream's architecture.

Upstream ships a local HTTP proxy (BSL-1.1 `proxy/` + `engine/`) that
mechanically rewrites the actual bytes on the wire: 15 type-specific
compressors selected by content detection (JSON, logs, code, diffs,
tables, tool schemas, terminal output, ...), deterministic, with recovery
— original bytes stored locally behind a handle, and at the storage cap
it fails closed to pass-through rather than silently dropping
recoverability. That is enforcement, categorically different from asking
a model to be terse.

So the honest framing is: hmd's caveman work is the INSTRUCTION path and
cannot enforce. The MECHANICAL path exists and is real — and hmd already
has one in headroom (the local compression proxy at 127.0.0.1:8787 this
very session routes through). They are complementary, not competing.

BSL-1.1 covers that code: not vendorable regardless of attribution. The
architecture is fair to learn from; the implementation is not ours.
