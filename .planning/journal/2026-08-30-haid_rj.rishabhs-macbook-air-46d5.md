## 2026-08-30T05:27:46Z — [COMMUNICATION] docs(analysis): agent stall enforcement — what landed and what it does not cover

STALL 196 vs quota 202 across this session: stall is within noise of quota
as the biggest agent killer, and unlike quota it is ours to fix.

heimdall-agent-resume reported interrupted agents but never acted, so
recovery depended on the orchestrator noticing by hand -- which worked
about five times today and failed the rest.

bin/heimdall-agent-watchdog is the enforcement layer: detect (reusing
agent-resume, not a second detector), PRESERVE first, then classify.
Verified live -- quota kills correctly marked do_not_retry, which is the
cascade that killed five agents at once today.

Records three honest limits: it only preserves worktrees of agents in the
interrupted list (measured: an unrelated dirty worktree was correctly
skipped), it is invoked rather than automatic (SubagentStop automation
NOT VERIFIED), and it recovers from stalls rather than preventing them --
prevention is brief discipline, not code.

## 2026-08-30T06:24:25Z — [COMMUNICATION] docs(analysis): watchdog missed its first real case — turn-limit stops are invisible to it

Found by using it. A metrics agent stopped at its 50-turn limit with 1
uncommitted file; 'hmd agents rescue' did not see it and the work was
preserved by hand, exactly as before the tool existed.

Cause: it reuses heimdall-agent-resume's report, which lists only agents
recorded as INTERRUPTED. Turn-limit stops are not recorded there. So the
tool covers the case that must NOT be auto-retried (quota) and misses a
common case that SHOULD be (turn limit, 40 this session) -- backwards.

Fix direction: preservation should key on the broadest available signal
(a worktree with uncommitted changes and no live process), since
committing is additive and safe. Classification can stay narrow.

Recorded, not silently patched: the tool shipped claiming a capability
its first real invocation did not deliver.

## 2026-08-30T08:12:46Z — [COMMUNICATION] fix(watchdog): preserve on the BROAD signal, not the interrupted list

First real use missed its case: a turn-limited agent with 1 uncommitted
file was invisible, because detection iterated only heimdall-agent-resume's
rows and that tool lists only agents recorded as INTERRUPTED. Turn-limit
stops are not recorded there -- so the watchdog covered the case that must
NEVER be auto-retried (quota) and missed the most common case that SHOULD
be resumed (turn limit, 40 this session). Backwards.

Adds 'sweep': any .claude/worktrees/agent-* holding uncommitted changes is
preserved, whatever the recorded reason. Detection breadth and
classification breadth are different problems and are now split --
preserving is additive and non-destructive so it takes the broadest
signal (over-preserving costs one commit; under-preserving loses work
permanently), while classification stays narrow and keeps driving retry
decisions from the recorded reason. Sweep makes NO retry recommendation.

LIVENESS IS A HEURISTIC, documented as one: in-process agents have no
per-spawn OS pid, so there is no liveness proof available. Sweep uses a
conservative staleness window (HMD_WATCHDOG_STALE_SECS, default 600s,
matching the harness stall watchdog) and skips anything modified more
recently. A sibling task shipped pid-less pool entries by assuming a
liveness signal existed today and wedged the tool; this does not repeat
that.

MEASURED on the real machine: 55 agent worktrees were carrying
uncommitted work. 'run' saw none of them. 'sweep' found all 55, preserved
21, and correctly skipped 34 as possibly-live.
